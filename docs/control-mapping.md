# FinShield AI: SOC 2 and ISO 27001 control mapping

Owner: Roopak Dureja. This maps FinShield controls to the **SOC 2 Trust Services Criteria** and **ISO/IEC 27001:2022 Annex A**.

**Wording:** these are **SOC 2-aligned controls** and **ISO 27001-aligned controls**. FinShield has no SOC 2 report and no ISO 27001 certificate: a SOC 2 report can only be issued by an independent auditor after an audit. HIPAA is out of scope: it is a US law for health data, and FinShield holds none.

**Sources checked (every ID marked verified was checked against these):**

- SOC 2: AICPA, *TSP Section 100, 2017 Trust Services Criteria for Security, Availability, Processing Integrity, Confidentiality, and Privacy* (criterion text, not points of focus).
- ISO: *ISO/IEC 27001:2022(E)*, third edition, 2022-10, Annex A, Table A.1 (control titles and text).

"What it asks" is our one-line summary, not the official wording. **Status** follows the same rule as the Indian regulation rows: `UNKNOWN` until each control is checked against the working build at CP4, then `IN_PLACE`, `GAP` or `NOT_APPLICABLE`. **Verified** means the criterion ID and text were checked against the official source.

## Notes

- The same rows are in `simulator/seed/compliance_controls.json` after Arvind's Indian regulation rows (`IN-01` to `IN-25`), with IDs `SOC2-...` and `ISO27001-A....`, `verify_clause: false` (verified) and a `source_url`. The Compliance screen reads this file through `GET /compliance`.
- Logging retention (CloudTrail 90 days, Step Functions logs 14 days) and Cognito MFA are listed as known gaps in `docs/data-handling.md`.
- KYC image labelling (unmasked Aadhaar flag) is a P2 item; if it is not built by the demo, change the A.5.34 row to describe only masking and the consent ledger.
